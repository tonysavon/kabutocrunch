# Calling Kabutocrunch from KickAssembler

Run these commands from the repository root (use `kcrunch.exe` on Windows):

```sh
python examples/make_data.py
./kcrunch --binfile --no-inplace -o examples/data.lz examples/data.bin
./kcrunch --inplace -o examples/data-inplace.prg examples/data.prg
java -jar /path/to/KickAss.jar examples/regular.asm -o examples/regular.prg
java -jar /path/to/KickAss.jar examples/inplace.asm -o examples/inplace.prg
```

Load either assembled PRG in a C64 emulator and RUN it. Both return to `done`
with the same 8 KiB of decoded data at `$4000..$5fff`; `done` loops forever
so you can inspect RAM. Replace that loop with your own continuation code.

- `regular.asm` reads an ordinary raw stream from `$8000`, into a separate
  output buffer at `$4000`.
- `inplace.asm` uses the compressor's calculated placement inside the output
  area. It reads the packed PRG's load/destination headers at assembly time,
  skips those four file bytes, and uses `ZX0_RAWDECRUNCH` with `INPLACE` defined.
  Do not relocate this packed stream independently of its destination.

Both select RAM with `$01=$34`, disable interrupts and clear decimal mode.
The raw decoder uses A/X/Y, flags and zero page `$f8..$ff`, modifies its own
code, and returns with RTS. Keep the decoder/caller and stack outside the
output region; restore banking and interrupts as appropriate for your program.

For the Dali equivalents, add `-dali` to **both** compressor commands and change
both imports to `../src/asm/dcrunch_dali.asm`. Keep the matching define and
macro calls. Native and Dali streams must use their corresponding decoder.

The files generated by these commands are ignored by Git. No game data or
external copyrighted fixture is needed.

To assemble and automatically byte-check all four combinations:

```sh
python tools/test_examples.py --kickass-jar /path/to/KickAss.jar
```

The header expressions mask each byte with `$ff` because KickAssembler's
`get()` can return signed byte values.
